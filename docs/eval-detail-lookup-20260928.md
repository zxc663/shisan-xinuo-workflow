## 二、改造内容

1. **语义扩写层**（references/detail-expansions.json，60 同义族）：手写 44 族（TOP 家族+30 域+挖矿词表）+ glm-4.5-air 独立扩 18 族（then 锚逐词面核验，12 族有效合并，6 死锚丢弃）。查询词含 if 变体 → 并入 then 词面锚。头行显式报「扩词: …」可审计。
2. **E6 假阳性修复（双闸）**：2-gram 回退命中 >20 条=全库共振判垃圾；首位条目 gram 覆盖率 <1/3 判不相关——双双诚实报 0。
3. **过泛护栏**：单一检索词命中 ≥100 条（≈27% 语料）→ 诚实报 0（「的」127→0；「错误」18 保留）。
4. **金样本扩容**：24→60 例三段制（46 正+8 负+6 扩写判别），负例/扩写例为本批首创段。
5. 实现面顺修：stdout 二次包装关 buffer 缺陷（模块导入场景炸 print）——已 UTF-8 跳过包装。

## 三、过程判例（自身踩坑即证据）

- 首轮 6 正例失败三根因：过泛护栏误杀单参数多词查询（「深拷贝 undefined 键 丢弃」基线绿被杀）→ 护栏条件改「唯一检索词」；扩写只在全零召回触发→部分召回（噪音先行）永不扩写 → 改常开并入；emit 截断 top-12 → 排序权重自然修复。**教训：护栏本身要进金样本回归（本轮护栏 bug 即被「基线绿」用例抓出）。**
- 新金样本期望编号逐一 grep details.md 实证（防「按印象出题」——NR16 同族教训 11 败 9 项现成）；2 例出题即被实证纠正（#294 无英文词面→转作扩写判别例；#280 词面不符→换词）。
- Mimosa 门对探针的 subprocess+变量、动态路径写盘拦截 ×3 → 改模块导入直测（CLI 端到端由本报告下方冒烟命令证真）+砍 json 工件。
