## §一 认知修正声明（本批的核心产出）

**承认**：项目长期把「渐进式披露」当作差异化卖点，并在 T1/T2/T3 三层叙事中把它从**行业本义（分文件按需加载：SKILL.md 精简+references 整文件按需）**私自延伸为**文件内容分段按层披露**（rules.md 拨盘小窗/大窗、G0 摘要常驻、T2/T3「按症状类打开对应条号段」）——后者平台机制不存在（设计档 rules-refactor §九两级证伪：加载单元=文件；分段依赖自觉=无结构锚，治理类全读实测 0 次）。

**保留的真资产**：①分文件架构（核心常驻/rules/details/flows 分册，触发时整文件进出——与 ATS 规范一致）；②两个真片段机制（`detail_lookup.py` 检索端口取目标条 + hooks TOP 每轮推送节选）；③判级锚定的文件级加载契约（rules.md 新契约）。

**修正后的一句自述**：分文件按需加载 + 细则检索端口片段取回；无文件内容分段机制，凡需要片段的一律走检索端口。
