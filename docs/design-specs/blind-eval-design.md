# 盲评实验设计档（P-D ③ · 细则 #373）

> 状态：**设计档（未跑批）**。本档回答「怎么证明这套工作流让真实软件工程结果变好」——
> 现有证据只证明「系统符合作者定义的行为规范」，不证明「使用后任务正确率提升」。
> 落档目的：把「该做什么实验」从口头承诺变成可执行方案，等排期与预算后再跑。

## 一、要检验的命题

- **H1（成本）**：Workflow 组的人机往返次数与 token 消耗高于裸 Agent 组（已有方向性观察）。
- **H2（返工）**：Workflow 组的返工轮次（同一任务被要求重做/纠偏的次数）低于裸 Agent 组。
- **H3（正确性）**：Workflow 组的交付物在盲评中正确率不低于（或不劣于）裸 Agent 组。
- **H4（风险）**：Workflow 组在高风险任务上的越权/破坏性动作发生率为 0，裸 Agent 组 >0。

**一句话**：本工作流宣称的不是「更聪明」，而是「更少乱做 + 更可追溯」；实验就要么证伪、要么量化这个交换比。

## 二、设计（预注册，跑前冻结）

| 项 | 规定 |
| --- | --- |
| 任务集 | ≥30 个真实任务（含小改 / 多文件 / 契约变更 / 高风险各档），来源=真实项目待办，**含作者未参与的任务** |
| 分组 | 对每个任务随机分配 A=裸 Agent / B=Workflow Agent；同一任务两臂各跑 1 次（配对设计） |
| 盲法 | 交付物去标识（去路径、去会话痕迹）后交**外部评审**（非作者、非被测模型）打分；评审不知分组 |
| 指标 | ①正确性（评审 0-3 分 + 关键验收用例通过率）②返工轮次 ③人机往返次数 ④token 与耗时 ⑤高风险动作次数（红线违规） |
| 样本量 | 配对 n≥30 才做区间估计；n<30 只报方向 + 明确标注「不足以推断显著」 |
| 预注册 | 任务清单、判分表、指标定义在本档冻结后才开跑；跑中改判据=作废重跑（承 `细则 #368`） |
| 见证 | 每次运行留可复跑工件（prompt / 输出 / diff / 验证命令 exit），供第三方复算 |

## 三、判读纪律

1. **不许事后挑指标**：五个指标全报，含不利项。
2. **成本与收益分开报**：往返/token 上升 ≠ 方案失败；只有在「返工与正确性无改善」时，成本上升才构成失败。
3. **机器判据优先**：正确性先用可跑的验收用例（测试/类型/契约/schema）判定，LLM 评审只用于用例覆盖不到的语义质量（`细则 #373`）。
4. **作废行有据**：环境失败（provider 报错/空输出）按证据签名剔除，与行为失败分开报（承 `细则 #368`）。
5. **结论带指纹**：任务集版本、被测副本哈希、平台版本、判据版本缺一不可。

## 四、成本与前提

- 成本：≥30 任务 × 2 臂 + 外部评审工时；探针/模型调用成本按实际计。
- 前提：①用户批准预算与排期；②能招到**非作者**的外部评审；③任务集可脱敏公开（不能公开则改用合成夹具并在档内声明）。
- 不做的情形：任务集全部由作者挑选、评审由作者兼任、样本 <10 —— 此时只能报「可行性试点」，不得报效果结论。

## 五、与既有证据的关系

- 现有 `EVIDENCE.md` 的 with/without 观察（N=1、非盲测、作者自评）**不满足**本档标准，故只能作为可行性信号。
- 本档跑完前，README 与发行材料**不得**出现「效果更好/更省返工」类结论，只能写「可追溯、可审计、防返工机制在位」（承 `细则 #373` ③）。
