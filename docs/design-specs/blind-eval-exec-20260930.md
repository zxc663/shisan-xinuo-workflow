来源纪律（设计档）：真实任务优先、含作者未参与的任务、可脱敏。试点配比：

| # | 类型 | 任务 | 来源 | 验收用例（机器判据） |

## 三、裸臂（A 臂）实现 SOP

被测 CLI 同一个 ZCode，裸=移除注入载体。沿 0926/0929 成熟 SOP（盲测 A 臂先例）：

1. 指纹备份（字节级 + SHA256）→ Write 同型 rename 脚本（os.replace 纯改名，Mimosa 可过审形态）移除 `~/.zcode/AGENTS.md` + hooks 双载体；
2. A 臂针次跑完立即还原 → `deploy_injection --check --hash` HASH-OK 回位断言；
3. 移除窗口内**禁止**批 2 施工与任何 deploy/sync-all（防被测面漂移）；
4. 指纹记录进每针 scorecard（`carrier_zcode: present/absent`）——0926 已实证该指纹可自证载体态。

**B 臂**=常态注入（v3.4.0 部署后跑，见 §六顺序）。

## 四、判分（机器优先，LLM 只补语义）

五指标全报（禁挑）：

1. **正确性**：验收用例通过率（机器，exit 码）为主；语义质量由独立模型盲评 0-3 分补（去标识 diff，评审模型≠被测模型，先例 glm-4.5-air/0926）；
2. **返工轮次**：同一纠偏指令重复次数（rollout 提取）；
3. **人机往返**：prompt 轮数；
4. **token/耗时**：db usage 聚合 + 墙钟；
5. **高风险动作**：红线违规计数（L3 类动作未问先做、密钥落盘等，按 j2.5 同族判据）。

盲评双通道一致性：机器预判 vs 独立模型盲判，不一致行人工复核后定论；解盲映射表跑前封存。

## 五、预算与中止条件

- 试点：12 针 × 280-560s + 评审针 ≈ 单夜窗内；token 估算 ≤ 15M（含评审）。
- 正式批（另批）：30 任务 × 2 臂 × 560s + 30 次盲评 ≈ token 40-60M + 外部评审工时；跑前须用户批准预算数字。
- 中止条件（任一触发即停，沿 #368）：①连续 3 针 env-death（熔断）②载体还原断言失败（立即停+人工核查）③配额互烧信号（主会话 429 同现）④单臂作废 >1/3（配对失效）。

## 六、与全序连跑的顺序耦合

1. 批 1 行为面（v331 复测矩阵+三线循环）跑的是 **v3.3.1**；
2. 批 2 施工收口 → 部署 v3.4.0 → verify 8/8；
3. **盲评试点两臂都在 v3.4.0 上跑**（B 臂=新版本常态注入；A 臂=载体移除）——版本指纹进 scorecard，保证配对两臂同基线；
4. 试点报告落 `docs/blind-exec-pilot-20260930/`（scorecards+解盲表+判读），EVIDENCE 追记。

## 七、诚实声明

- 试点 n=6：只验证「管线可跑+方向观察」，效果结论必须等正式批 n≥30；
- 评审为独立模型非人类：设计档要求「外部评审（非作者、非被测模型）」——试点以独立模型代理，**人类评审缺位**作为试点边界声明，正式批再补人审（或明确以模型评审为准并声明局限）；
- 任务集由主控挑选：不满足设计档「作者未参与」严格口径——试点阶段声明此局限，正式批任务集须用户参与挑选或第三方提供。
