## 二、视觉规范

- **画布**：`viewBox="0 0 1200 N"`，N 按内容；浅色背景底（#FFFFFF 或 #F6F8FA）+ 浅灰描边（#D0D7DE），GitHub 暗色模式下仍以浅底显示、可读。
- **配色**：正文墨 #1F2328 / 次级灰 #57606A；主色蓝 #1F6FEB（要点）、绿 #2DA44E（成功/默认道）、红 #D1242F（警戒/L3、边界声明）、紫 #8250DF（标记专用）。
- **字号**：图内顶部小标题 22 bold；节点主标题 20 bold；正文 16；行距 24。
- **节点**：圆角矩形 rx=12，主流程实线、侧注/边界虚线（stroke-dasharray 6 4）。
- **连线**：垂直/水平直线 + 三角箭头（`<marker>`）；交叉处不悬空。
- **约束（静态 SVG 硬规定）**：无 `<script>`、无外部 href/xlink、无位图、无外链字体——GitHub 会 sanitize 拦截；中文文字用手工分行 `<text>`/`<tspan>`（不依赖自动换行）。
- **文本长度**：主列文案每行 ≤ 40 汉字（640px 内），侧栏每行 ≤ 18 汉字（300px 内）。

## 三、口径锚点（作图时逐条对齐，防漂移）

1. 三层承载 = 记忆层（每会话在场锚点 · templates/memory-anchor.md）＋ 规则层（injection-core 核心全文）＋ 配置文件层（hooks/全局设置）；按需注入只写应用层（精简纪律 + 询问规则层，不写记忆层）；配置/记忆层含凭据走环境变量不落明文。
2. 三级跑道 = L1 快速通道（一句话复述→最小修改→最小验证→一行汇报）｜L2-S 短工作流（对接真相清单→复述 3 短行→免 plan→执行+最小验证→GATE 行，小模块默认道）｜L2-F 完整 9 步（大模块，每步出口产物门禁）。
3. 三问分流 = ① 跨 ≥3 包/跨层？② 涉契约·架构·迁移·发布·安全？③ 用户点名按流程/严格？→ ≥2 命中 = L2-F；L3 封闭清单 6 项（密钥/权限｜数据删除｜数据/服务迁移｜对外发布｜架构选型｜超预算破坏性操作）命中 = L2-F + 暂停先问。
4. 触达三件套 = 注入三层（平台注入）＋ 项目承载（memory 一档制 + project-info 六节 + 项目级规则文件）＋ 委托纪律包（子代理 prompt 内联最小纪律包）；边界 = 提示词范畴 ≠ 机制保证，hooks/SessionStart 触发器可闭环机制级触达。
