## 方案：查询扩写（query expansion）+ 2-gram 垃圾护栏
### 1. 语义扩写层（可移植语义，数据即语义）
- 新数据文件 `references/detail-expansions.json`：`{"rules":[{"if":["文件未读","not been read","编辑器报未读"],"then":["Edit","not been read"]}, …]}`——每条=同义/意译/英文/口语 → details.md 词面锚（真实存在于条目文本的关键词）。
- 生成：核心 ~50 族人工（TOP 家族+30 域高频同义，作者域知识直写）+ run_task(glm-4.5-air) 两批补 широт（同义/英文/口语变体），合并去重。
- 运行时：查询串包含任一 `if` 词 → 追加 `then` 关键词进检索词集，命中头行显式报「扩词: …」（透明可审计）。评分保持单路径（exact×3+parts×1），零校准成本。

### 2. E6 垃圾护栏（负向诚实）
2-gram 回退触发前加两道闸：
- 命中条目数 >20 → 判垃圾（真症状不会全库共振）→ 诚实报 0+提示换词；
- 首位条目 gram 覆盖率 <1/3 查询 grams → 同上。

### 3. 金样本扩容（24→≥60）
- +20 正例：换措辞/英文/口语（如「编辑器说文件没读过」→294、「copied object lost keys」→262、「端口被占用 EADDRINUSE」→295），期望编号逐一 grep details.md 实证；
- +10 负例：垃圾串/纯英文乱码/单字泛词，期望=诚实 0；
- +6 边界：扩写层专测（用 `if` 同义词查询，验扩写生效）。
- 指标：正例召回率／负例误报率（改后必须=0）／首命中数；改前改后双跑出对比。
