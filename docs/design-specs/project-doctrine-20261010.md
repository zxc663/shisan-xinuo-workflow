# 项目经营条例（如何做好本 Skill 工作流项目 · 反向更严版 · 2026-10-10）

> 前提事实（证伪方优先信）：写多/写细≠更好——外部四路（指令遵循退化/注意力稀释/延迟/成本）〔文献方向级〕＋本仓自测三件〔最高级〕：散文锚 0/20 vs 结构化 65%、无条件全读实测 0 触发、加载≠照做 ~1/12。**所有条例按「先活过反证」编写。**

## 六条条例（每条：主张→反证压力测试→存活形态）

**1 · 分面记账制**：每个工件先定面（常驻/触发/检索/机制/证据/档案），按面记体积账——常驻 6K 硬顶（已机检）、主文件 <500 行、检索面按命中效率验收。
*反证*：分面会不会是新仪式？→ 分面不是发明是承认（加载机制本就分面）；记账已有实例（零和+等量压缩+核心字符门禁）。

**2 · 证据准入+对称退役**：新增=真实失败+反复出错（#38/双击晋升）；**新增的镜像义务=退役**，每批强制删≥增或记账（R4 刀即实践）。
*反证*：删过头伤人（release-notes 系列判例）→ 三层消费面测试兜底（文档引用/系列完整/工具门禁消费——任何一面在场即保留）。

**3 · 形态优先于数量**：同内容先改形态（结构化字段/正面白名单/示范件），再谈删减——58 字结构化赢两百字散文 65 个百分点。
*反证*：形态结论是 ZCode 实测，跨平台外推未验证 → 如实标边界；「结构>散文」有跨源方向性支撑，可用。

**4 · 机制优先于文本**：能机制化的不进文本（exit code/哈希/hooks 推送/字符门禁）；机制化判据复用 product 三判据（可机器判定+决策点拦截+成本<返工）。文本只承担语义判断。
*反证*：机制有维护成本（判据版本/回归）→ 已付基建（JUDGELOG/金样本）压低边际；且**机制失效可见（门禁红）、文本失效不可见（静默跳过）**——不对称支持机制化。

**5 · 验证外源制**：主证据=判据生成源异源（真实失败/外部植入/schema/平台机制）；自产自验（自写测试、自评）不作主证据（deepSwe 实证+本仓三层精化）。
*反证*：外源贵且窄 → 分级使用（exec<cover<invariant<indep），外源押关键断言，不求全覆盖。

**6 · 读者经济制**：三个读者面各有成本函数——使用者（首屏/导航）、下一会话 AI（上下文预算）、维护者（决策审计）。每件产物写明服务谁、谁付成本（导航取代删除；archive 判据；加载契约均此例）。
*反证*：三读者会互伤（为 AI 伤人类）？→ 实证未冲突：结构化对两者皆好；冲突只发生在体积分配，按面切分解决。

## 条例对己的预注册证伪（反向更严落到项目自身）

- **度量可证伪**：①常驻面不涨（机检）②按需面引用率（思考/规则引用探针（v4.1.0 已注册））③事故账 ≥10/90 天（incident ledger 执行中）④第三方对照累积（deepSwe 型数据逐步确证方法论假设）。
