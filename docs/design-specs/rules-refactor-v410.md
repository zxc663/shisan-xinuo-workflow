## §二 用户三修正（B → B+ 的增量）

1. **双模态预算**：加载策略不按「省 token」单目标——按窗口分档。小窗 agent：仅红线组常驻摘要；大窗 agent：红线+决策组可常驻，其余仍按需。策略是拨盘（元数据标「必须常驻/可常驻/按需」），不是定死。
2. **组级场景分型**：组按「什么时候在场」重排（见 §三），每组头部一句场景声明；交付纪律归「收尾场景组」。
3. **执行层次三分**：`载体=机制（hook/门禁名）｜自律（提示词）｜人侧与平台调度`。第三类的判定原则（v1.1 修正）=**agent 的时间性是载体的函数**：离散调用型会话无持续存在——跨时间义务须写成触发-响应式（触发者+被触发时行为）；**连续型载体（目标模式长班/cron 轮值/常驻监控会话）有持续时间空间，可自持观察窗**——跨时间义务按载体分载，不一刀切。

### 通用性分层（v1.1 新增·#28 专项）

rules.md 自称「通用版、无个人定制项」，但 #28 混入大量平台实证细节（Skill 工具注册校验示例〔browser_use〕、skill-usage.md §0 引用、委托纪律包分级定版细则、「实测 0 加载」数据）。处置：
