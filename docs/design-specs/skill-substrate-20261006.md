# 技能基质层（Skill Substrate）· 设计档

> 状态：**待用户确认**（设计确认门——确认后才施工）｜落档 2026-10-06｜判级 L2-F
> 来源：用户令「根据产品工程的思想继续优化——不是对 skill 本体内容，而是对 skill 本身的基质层（skill 使用 basic skill 之后要用到的思想）」+ 四项拍板：要素四项全含（层栈+门/装配序列/缝合契约+接入模板/归因追溯）· 落点=升级 `references/skill-usage.md` · 单文件版加「装配接口」段 · 设计档先行
> 术语校准：**basic skill = 基础纪律技能**（纪律底 = 本仓库核心包 / 单文件版）；「SQ」为用户笔误，实义=**skill**。

## 1 目标与定位

- **定义**：技能基质层 = 以基础纪律技能（S1 基质）为底、其它技能在其之上「装配/协同」的整套思想——回答「skill 使用 basic skill 之后要用到的思想」。
- **不动本体**：不改任何技能的本体正文；本层是「**协同面**」——落在既有承载件 `references/skill-usage.md`（升级）+ 基础技能头部「装配接口」段（6 行）。
- **与产品工程同构**（移植思想，不搬内容）：

  | 产品工程 | 技能基质层（本档） |
  |---|---|
  | 层级栈 L0-L10 | 技能层栈 **S0-S4** |
  | 层级门三段式（定位→检上游→放行/回补） | 层级门三段式（定位→**检基石**→放行/回补） |
  | 铁律「实现层完整性≠产品工程完整性」 | 铁律「**技能本体完整≠基质完整**」——技能再完整，纪律底缺位=缺基石，禁越级下沉 |
  | 契约三件（硬层/软层分界；**禁为填表而填表**） | 缝合契约（六硬字段 + 档位自适应；外来技能最小三字段） |

- **马尾辫原则内嵌**：复用优先（升级既有 skill-usage，不新建平行件）、最少规矩（层 5 / 门 3 步 / 契约 6 字段 / 序列 5 步）、删除优于新增。
- **单一权威**：本层只做「定位 / 门 / 契约 / 归因」；三层加载模型、渐进读取分类、子代理注册纪律、三缝合点等**既有内容归 skill-usage 原节**——本层只引用、不复制。

## 2 技能层栈 S0–S4（装配坐标）

| 层 | 名称 | 内容 | 本仓对应 |
|---|---|---|---|
| **S0** | 平台注册层 | 「能不能被发现」：可用技能注册清单 / 注入面 | 平台机制（skill-usage §0 已定义，引用） |
| **S1** | 基础纪律层（基质） | 「怎么做事的底线」 | 核心包 / 单文件版（basic skill） |
| **S2** | 家族治理层 | 流程分册 / 审查角色 / 产品工程能力 | flows / roles / product |
| **S3** | 专业人员层 | 把活干得更专业的外来技能 | ponytail、ui-ux-pro-max、docx/pptx… |
| **S4** | 项目约定层 | 项目现实（规则文件 / memory / 既有文档）——横向最高裁量（用户现场指令在其上） | 项目 AGENTS.md / memory / project-info |

**命名纪律（防混淆）**：裸 `S+数字` = 技能基质层（本档）；**不与**产品包 `L0-L10`（产品层级）、`档0-档3`（风险深度）、`判级 L1/L2-S/L2-F`（工作流）混用。

**装配语义**：下层是上层的地基（技能叠在纪律上）；S4 是项目现实，覆盖之上；用户现场指令 > S4 > 纪律面仲裁序照旧（仲裁序单一源=注入核心）。

## 3 层级门（三段式：定位 → 检基石 → 放行/回补）

1. **定位**：先写出来「这是个哪层的问题 / 该用哪层的技能」（如「这是 S3 视觉打磨任务」）。
2. **检基石**（三项必查）：①该技能在 **S0 注册清单**里吗（未注册=文件存在也触发不了）；②**S1 基础纪律**在场吗（产出将由谁的门收口）；③**S4 项目约定**读了吗（项目优先）。
3. **放行/回补**：三项齐 → 放行；缺 → 停下回补（先装基础技能 / 先读项目规则）——**禁越级下沉**（没纪律底直接用专业技能=缺基石）。

**触发拦截表**（最小 5 行；引用既有节，不复制内容）：

| 触发信号 | 必查 | 缺项动作 |
|---|---|---|
| 直接上领域/专业技能的活（未装基础技能） | S1 | 先装基础技能（单文件或核心包），再谈技能 |
| 加载 / 使用外来技能 | S0+S1 | 未注册→先注册；纪律不在场→声明降级（跳过+声明） |
| 子代理跑带技能的活 | 子代理注册面（skill-usage §0 既有） | 未注册→留主会话或换 agent 类型；最小纪律包内联（rules §28） |
| 多技能说法冲突 | 仲裁序 | 按仲裁序裁决 + 留痕；同因两次升格常设 |
| 技能产出要交付 | 出口交门 | 进基础技能的 GATE / 承载 / 交付五查 |

## 4 装配序列（基础技能装载之后：五步）

1. **平台与注册面**（S0）：确认目标平台注入 / 注册面可达（skill-usage §0）。
2. **基础纪律在场核验**（S1）：注入副本或技能副本 + `zxc663` 自检。
3. **能力发现**：S0 清单扫描 + 能力检索（核心 §2.1：命中即用 / 未命中才自写并归因）。
4. **按层装载**（S2/S3 按需）：渐进 vs 完整读取分类 = skill-usage §4（单一源引用）。
5. **缝合与归因**：按缝合契约对接；用完不驻留；使用记归因（§6）。

> 五步只规定「顺序与检查点」；各步细则一律引用既有节——本层不产生第二份说明。

## 5 缝合契约（六硬字段）+ 接入模板

| 字段 | 内容 | 判定 |
|---|---|---|
| 依赖声明 | 假设 S1 在场？不在场时的降级行为 | 必填 |
| 回指 | 指向基础技能（名称 / 位置） | 必填 |
| 仲裁位 | 「不覆盖纪律层」；冲突按仲裁序 | 必填 |
| 出口交门 | 产出落点（GATE / 承载 / 交付五查） | 家族包必填；外来技能可 N/A |
| 单一源 | 不重复定义纪律层（防棘轮） | 必填 |
| 归因 | 使用记录落点（caps= / 流水 / 账本） | 必填 |

**档位自适应（禁为填表而填表）**：家族包 = 六字段全；外来技能 = 最小三（依赖 / 回指 / 仲裁位），其余 N/A 声明即可；一次接入一次填写，**不建登记册**。

**接入模板**（一页，施工时内联进 skill-usage §9）：

```markdown
### 技能接入声明（贴入技能头部或 references 首节）
> 适用：本技能与「基础纪律技能（basic skill）」同场使用时。
- 依赖声明：本技能【假设 / 不假设】基础纪律在场；不在场时 →【降级行为 / 自含照常】。
- 回指：基础技能 =【名称 / 位置】。
- 仲裁位：本技能不覆盖纪律层；冲突按仲裁序。
- 出口交门：【产出进入 GATE / 承载 / 交付五查 / 不适用】。
- 单一源：本技能不重复定义纪律层条款。
- 归因：使用记入【caps= / 流水 / 账本】。
```

## 6 使用归因 / 追溯（三级落点，零新字段）

① **GATE `caps=`**（既有 12 字段之一，**不改定版**）记「用了哪些能力 / 技能」；② **agent-log 流水行**加「技能账」一要素（用了哪些技能、哪层、出口产物）；③ 产品包在场 → 其 `decision-ledger` 记裁决（三缝合点照旧）。

**追溯效果**：任一交付可回答「哪些技能参与了、各自出口落在哪、冲突怎么裁的」。
