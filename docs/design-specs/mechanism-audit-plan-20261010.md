## §一 评估框架（三层 × 三问）

每受审对象过两层镜头：
- **三层镜头**（用户修正版）：内容层（规则文本是否含 agent 行为模式洞察，非人类常识搬运）｜触达层（提示词级 vs 机器级）｜验证层（遵守与否可否机检/回归/反作弊）。
- **三问镜头**（用户原始四问）：必要性（这条机制/钩子/分册删了会怎样——有失效案例吗）｜设计（形态是否踩已证伪基点——分读教训适用）｜验证状态（设计有没有被真实跑过——部署面哈希≠行为面）。

**两个已确认的真短板=主攻方向**：
- A（内容层）：agent 心理洞察散落（#25 不感知压缩/#28 子代理不继承/#26 全读 0 触发），未集中成 superpowers 式「反借口红旗表」——已有胚子=注入核心「借口拦截」（危险词「显然/只是」）仅一句。
- B（触达层）：提示词级触达被自家实测证伪（散文锚 0/20 vs 钩子推送 65%；B 段 0-1/12）——升级路径=钩子/门禁/结构锚，落点在 ZCode 深耕+跨平台模板规范。

## §二 轮次计划（目标模式·每轮自主推进·批间停审批门）

- **R1 对照组加验+机制面审计**：①轻量验证「验证层独一档」（PRP/BMAD-METHOD/Aider conventions 三家搜索级——各答一问：有没有对规则遵守做机检/回归/反作弊；一轮为限）②platform-adaptation.md 全文过三问镜头（§2.1 实测表/§3.2 钩子设计/§7 能力矩阵的必要性与验证状态——哪些「设计在档但从未跑过」）。
- **R2 存量钩子必要性+flows 审计**：①ZCode 四脚本×六事件逐个过「有没有拦下过真问题」（hooks 日志/agent-log 实证检索——top_push/carrier_reminder/post_tool_guard 各自的触发实效）②flows 九分册+15 节过三问（哪分册从未被路由到=休眠候选）。
- **R3 短板施工设计**（审后若确认）：A=红旗表规则文本设计（借口预测→逐条堵死，superpowers 形态+本仓实证词条）；B=ZCode 钩子深化清单+跨平台模板规范（templates/hooks 验证协议）；产物=设计档+施工清单→**停审批门**。
- **R4 施工批**（批准后）：按清单施工+验收+留档。
- 停点：L3 域（发布/密钥/破坏性）与严重阻塞照停；每轮 GATE 收口。

## §三 验收线

## §五 三缺口裁决与并入（2026-10-10 · 用户五家逐条对读+档案核实）

**核实判词**：①「243 条零触发候选退役」——档案零命中（在案=#103 单条退役 406→405+冻结零和），**未定论挂起待源**；②「违背自家调研结论」——时间线修正：调研结论（2500 仓「只在反复出错处补规则」）成文于 10-10 rules 重构档，长胖（314→406）在其前（09-30 循环），成文后已调头——**准确罪名=哲学未入宪法**（无「删多于加」元规则，胖靠批次减肥不靠宪法防胖）；③「C2 机器闭环缺失」——**完全证实**，且对标档:48 自认修法「GATE cmd 字段天然是收敛判据载体」。

**逐句对读结论（#19 vs PRP review loop）**：PRP 把「重跑到绿」写成机器参数（--max-cycles 3+exit 0 权威绿判），我们把同形状写成 agent 承诺（「重跑限 3 轮」）——**限 3 轮≈max-cycles 3，差的不是设计是绑法**（C2 微缩标本）。#17 vs spec-kit=对象不同（判断启发 vs 模板+机器强制），非同条纪律两写。

**并入 R3 的三个施工方向**：
- **A′ 红旗表（缺口 1）**——反借口武器，每行挂自家实证（比 superpowers 的更有据）：「这是小任务不用判级」→L1 也是分出来的，任务都是任务｜「我记得这条规则」→规则会演进（j2.5→j2.6 型），编号引用读当前版｜「先看看代码再说」→#42 实况调研是规则不是前奏｜「压缩了没关系我记得」→#25 你不感知被压缩，状态行在就信状态行｜「子代理会自己守规矩」→#28 不继承纪律载体（实测）｜「这条规则小题大做」→在场成本=每次一行，缺位成本=一次返工｜「等会再补 GATE/留档」→#41 会话随时被截断，结论即时落盘｜「显然没问题」→借口拦截既有胚子（危险词自检）扩展。
- **B′ 删多于加元规则（缺口 2）**——BMAD 句式入宪法层：「长与模糊每轮付税，极端案例只在发生时付——不给极端案例加指令；宁可删一条指令，不给它加对冲句」+Cursor「重复犯错才加规则」为本仓细则准入门槛的成文化。落点候选=SKILL 写作分层节+details 维护规则节（**注意：injection-core 5,991/6,000 仅 9 字符余量，若入核心须等量压缩**）。
- **C′ GATE 收敛语义（缺口 3）**——「cmd 字段=收敛判据载体」落地形态设计：任务级 GATE 的 cmd 从「可重跑命令」升为「**循环到绿命令**」（exit 0=权威绿判，超限停=stop_reason），对齐 PRP --validate；gate_audit 从事后抽检升「循环未到绿禁收口」门禁——R3 设计、批准后施工。

**最小动手原则适用**：A′/B′/C′ 各挂「对应真实问题」（散文锚 0/20=反借口缺武器实证／时间戳滞后+五版本漂移=宪法缺位实证／GATE 事后抽检=C2 自认），无真实问题对应的动作不做。

## §六 体裁纠正与 scope 根因（2026-10-10 · 用户第三轮对读采信，计划升 v1.1）

**Scope 根因论采信（本轮最强解释）**：47 条不是内容更多，是**「通用所有平台所有项目」的 scope 承诺逼出来的**——每条须处理载体差异/例外/指针皆因 scope；治理密度（来源/证据/触达端口）=scope 过大×哲学缺位的双重代偿成本，非优势。此论统一此前全部批判（为何带元数据/为何体量大/为何治理重）。**注脚保留**：判据/scorecard 层验证的对象是哲学层管不了的（任何条数的遵守与否都要测，三家不验证≠不需要验证）。

**B′ 扩容**：元纪律从一条扩为三条——①删多于加（BMAD）②**没有 maintainer 的结构不要建**（PRP「Structure implies a maintainer」；在案活案例=待硬化标签〔本会话已删〕/reference-sources 五版本漂移〔v4.0.0 verify C 门已锁〕/活头部时间戳滞后〔F7 实测+P-C 批药在〕——病真药在，但缺源头哲学）③反借口武器（A′ 不变）。

**两个待办挂起**：①用户预告「有两条比三元纪律更该加的『诚实与自我怀疑』类规则」**待揭示**（主控假设：断层诚实〔压缩/截断后承认断层不脑补衔接，挂 #25+状态行归零+相邻会话错位 +54% 实证〕/完成诚实〔不表演完成，挂假完成 22.6% 实证〕——待用户原意对齐）；②**删/下放/提炼清单**=R4 前置件（用 scope 哲学逐条过 47 条：操作级下放 flows/details/对冲句删/洞察原料提炼进红旗表），主控出初版用户校。
