## 二、分层优化：避免无意义 token 消耗

**注入面（结构性）**：
- injection-core 5,532 字符常驻——cache_read 语义下热会话成本低，但**新会话冷启动与无头面是全价**；本轮新增必问底线后复核保留集：判级/红线/GATE/状态行/必问底线/TOP 检索端口=T1 定义内，暂不再砍（TOP 内联是触达主通道实证，砍=回退触达）。
- **重复面检查**：项目级 AGENTS.md（被测项目内）与全局注入的重复段落——被测项目承载建了 AGENTS.md 后，全局核心与项目规则的重复义务（开工四步口径）各说一遍=可接受（承载回指），但**hooks carrier_reminder（353 字符）与注入核心常驻保留集同文**——交互面双重注入，无头面唯一载体：保留，标记「已知重复、无头面保险」。
- 注入核心**不再扩**：后续新纪律一律入 details（T2/T3），注入核心只收「每会话必须在场」的判级/红线/必问底线级条款——本轮 #306 十维清单正文在 details，核心只留五维+回指，即此原则的执行样例。

**行为面（新观察维度，路测 v7 判分）**：
- 超长思考一次性输出（365 秒内心起草全部代码）=重推理成本+不可审计——候选纪律：长任务先落 plan/骨架稿再填肉（与环节 5 同修）。
- 工具域故障深挖（走查撞自动化层坐标偏移 8 轮）——候选纪律：工具域/应用域快速归因，≤2 轮识别即换通道并留档教训（本轮被测会话最终做对了，但耗时 8 轮）。

## 三、资源利用纪律（Skill / MCP / 文档）

- **开工盘点可用资源**：平台注册的 Skill/MCP 清单在开工时扫描，计划中声明本任务用哪些+用途（本轮被测会话自主用了 browser-use✅，但属自发非纪律）。
