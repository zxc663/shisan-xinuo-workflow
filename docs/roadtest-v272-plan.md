## 1. 压缩机制取证结论（09-13 深夜实证，判分依据）

- **触发**：自动压缩阈值=有效窗 ×95%（zcode.cjs 常量 `sGr=95`+`shouldAutoCompact/getAutoCompactThreshold`）。**实测下界（CALIB 探针 sess_a198ac66）**：ctx 涨至 **246,401 tokens 未触发**（30 req/4.2M in/236s，compact_rows=0）→阈值 **>246.4K**；S-A 现场 ctx 曲线+压缩事件将钉死真实阈值。**手动 `/compact [instructions]` 命令已证注册**（GUI 可用，runs core manual compaction path）。
- **达标策略（据 CALIB 修订）**：40+ 轮内自然压缩 ≥3 次不可保证（阈值高+v9 S-A 243K 零压缩旁证）→**手动 `/compact`（附保留指令）=达标主路径**，自然触发=加分观测（触发即记录方式/时点/前后 ctx）。
- **落点形态（真实样本实证）**：压缩=插入 user 角色 message，data 含 `"summary":{"title":"Compact summary","body":"Summary:\n1. Primary Request and Intent:…"}`（样本 sess_66effb58 博客项目会话，882 message/压缩 1 次位于会话中部延续点）。db 可数、rollout 逐请求可扫。
- **衰减机制推论（S-A 待实测）**：压缩后上下文重建，messages[0] 变压缩摘要→交互面注入锚（messages[0] 工作流核心）面临冲掉；hooks SessionStart 不重触。→「压缩触发器」的纪律存活率=本轮核心量测量。
