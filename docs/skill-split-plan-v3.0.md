**背景与目标**：依据四份调研档，把「管的太宽太泛」的现状重构为：管「怎么做」的纪律元核心（常驻、可预期）+ 按需工具箱家族（流程/角色），同批落地利用率治理与行为缺口补丁。**判级：L3（架构选型+破坏性重组，方向已获四轮对齐授权）；流程走 L2-F 完整 9 步。**

**产品五问**：①诉求拆解=纪律收紧成常驻核心、知识/流程/角色下沉按需包，让纪律可预期、成本可复测、能力不闲置。②被否候选=C 多 Skill 家族（元治理分裂）｜A 单入口强化（维护代谢+分发目标无法兼顾）｜知识包首版（无内容面，v3.1 候选）｜Tool-Search 式结构性延迟加载（平台无机制，改清单匹配）。③返工成本=不拆则密度继续涨+利用率靠人工；拆的返工点=包边界估错，对冲=独立可装+依赖声明+每批探针回归。④边界不做=不碰 hooks/provider/model；不动 v2.9 已发行物与历史 dist；本轮不发行不推送；knowledge 包不建；「主控/并行/多分支」实践痛点不做；不逐条删细则。⑤验收=见下方「验收标准」。
