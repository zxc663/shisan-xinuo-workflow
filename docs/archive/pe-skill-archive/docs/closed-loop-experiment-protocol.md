# 高风险特征闭环实验协议（2026-09-23 立 · 载体已定）

> 目的（严格限定）：证明**一条**高风险 Feature Contract 可以闭环——「一个自然语言 Feature，可以被转换成机器可检查的 Product Contract，并一直追踪到真实运行证据」。**不**扩展成完整 Product Engineering；失败即记录失败，不修饰。
> 依据：用户附呈三方讨论（先证明闭环，先例：删除/恢复/权限/异步；不选普通 CRUD）；three-definitions.md §3.3（产品工程 = 把完整性翻译成可判定性）。

## 一、载体

- 工作区：**新建** `D:/产品工程闭环实验/`（greenfield，空目录 + `git init` + 初始 commit = 回滚点）。
- 任务（自拟，小型但真实）：**「带回收站的收藏清单」**——收藏 / 删除 / 回收站恢复 + 撤销窗 + 异步导出 + 删除权限。
- 为什么选它：三条 L3 触发线齐备（删除·恢复｜异步·长任务｜权限），体量可在单会话内闭环。

## 二、必须逐环留证的链路（十环：环 0 上游 + 环 1-9）

| # | 环 | 产出物 | 判定 |
|---|---|---|---|
| 0 | **产品对象六问** | 职责句 / 能力清单 / 主功能标记 / 页面级闭环八组 / 可运营性（`references/product-object.md`） | **缺答=停**；产出落设计档 |
| 1 | Feature Intent | 一句话意图 + 非目标（软层，落账本） | 非目标非空 |
| 2 | 六问翻译表 | 每问有答案 | 缺项=交互债，停 |
| 3 | State Model | `docs/contracts/<feature>.json`（statechart 为源） | statechart-gate：无死端 / 全可达 / 错误态有恢复 |
| 4 | Recovery Model | 每个错误态的出路行（动作 + 落点） | **出路目标存在性**（禁死页 / 死函数） |
| 5 | Implementation Trace | spec-trace 双向（功能行 ↔ 界面元素） | 双向断裂 = 0 |
| 6 | Runtime Evidence | 命令 + 退出码 + 真渲染证据（截图 / DOM dump） | 无证据不得声称已验证 |
| 7 | Gate | 各门禁 `--selftest` + 实跑 exit 0 | 命令原文 + 真实退出码 |
| 8 | Decision Ledger | 为何这么定（≥1 条：删除语义 / 权限模型） | 一行能说清 + 出处 |
| 9 | Regression | golden sample：改一处后重跑 3-7 环 | 同一可重跑命令 exit 0 |

## 三、反向检验（「缺失可检出」的实证 —— 本协议核心）

正向闭环只证明「能做到」；**必须做一次反向注入**才有资格宣称「缺失可检出」：

1. 从已闭环的 statechart 中**人为抽掉**一条错误态的恢复转换（或删掉一条出路的落点）。
2. 判读：门禁 / 走查是否**必然**标红（statechart-gate 死端与全可达检查 + 出路存在性检查）。
3. 若未被检出 → 记「缺失不可检出」为**诚实负结论**——这正是产品工程要补的缺口，进账本与遗留。
4. 对照组要求（负向结论纪律）：注入前先跑一遍全绿（同命令），确保红是注入引起的，不是环境噪声。
5. **强变异作正向对照（2026-09-23 补）**：除"抽一条出路"外，必须再做一次**强变异**（抽掉该错误态的全部出边）——它应触发死端+无出路双报。若强变异也不报，说明门禁整体失效（而非判据粒度问题），结论须写「门禁无效」而不是「缺口存在」。
6. **证据标准（2026-09-23 补，来自本次最大的报告缺口）**：每条注入证据必须三件齐全——**① 命令原文**（可复制重跑，含参数与文件路径）**② 变异 diff**（证明注入确实发生）**③ 真实退出码**。缺任一，该条证据在本协议下不成立（"可重跑工件"在报告内不成立）。
7. **可重跑优先**：能把注入与断言写成脚本的，一律写成脚本（先例＝设计部 `docs/reverse-injection/verify.py`：自动构造变异 → 跑门禁 → 硬断言期望命中 → 生成证据档），报告只引用其输出。

## 四、证据通道（能力盘点）

- 真渲染证据：browser-use（`control-browser` 技能）截图 + DOM dump；不可用时降级为 `curl -s -o /dev/null -w "%{http_code}"` + DOM 字符串断言，并在报告标 `degraded`。
- 命令证据：每条 = 命令原文 + 真实退出码（GATE 三挂靠）。

## 五、预算与止损

- 时间盒：一个会话（≤2 小时）；轮次上限 = R1 建链路 / R2 反向注入 / R3 回归。
- 超预算未完结：降级最小验证交付并在 exempt 标 `unresolved`（工作流 §6 止损交付）。
- 不 push 实验仓；报告与账本写回设计部仓库。

## 六、诚实声明（写在报告首行）

单链路、单会话、无对照组；结论只答一句：**闭环成立 / 不成立 / 不可判定**，附十环证据与反向检验结果。模型随机性未消除——结论限定「本实验中成立」。
