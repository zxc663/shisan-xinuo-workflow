# H 组定位 · 功能流程状态设计（蓝海定稿，2026-09-21）

> 触发：用户「设计 Skill 只设计怎么做，不设计各功能的流程状态等，我们应考虑」。
> 定位声明：**设计类 Skill 的红海=手法层（怎么做才好看好交互：样式/组件/动效/文案）——hallmark/taste/impeccable/emil/vercel 全在此层；蓝海=结构层（这个功能的流程与状态该怎么被设计出来：有哪些态、怎么流转、流转怎么被感知、走不通怎么办）**。本 Skill 的核心交付物=结构层的工件化（六问翻译表+态+转换矩阵），判定表只是辅助。与 9.71「30 万」同源：30 万的差价就在结构层完整性。

## 1. 学科挂靠（F 档规矩：先查成熟框架）
- **Statecharts（Harel 1987，《Statecharts: A Visual Formalism for Complex Systems》）**：功能状态设计的正式学科——层级状态/并行区域/守卫/转换/动作。**它是可执行的数学对象**：可模拟、可模型检验、可生成测试。
- **XState（前端工业实现）**：statechart 的 JS/TS 实现——JSON/TS 定义状态机，可视化、可跑、可出测试用例。
- **流程建模**：user flow / task flow / wireflow（UX 惯例三件）；Garrett 结构层（F 档已挂）。
- **Nielsen #1**（系统状态可见）+#3（用户控制：撤销/逃逸）=状态设计的启发式根基。

## 2. 技术路径升级：态+转换矩阵落成机器可读 statechart
六态矩阵此前是文档表格（人读）；升级：**翻译表/态+转换矩阵的源格式=statechart JSON/TS（机器读），Markdown 表格只是渲染视图**。收益：
1. **无死端检查**：「错误有出路」在状态机层的严格表述=每个非终态至少一条出边；图算法可查（DFS/BFS）。
2. **全可达检查**：每个状态从初始态可达——不可达态=假想态（写了没人能到）。
3. **spec-trace 消费**：界面元素的状态绑定可回查 statechart（反向追溯的数据源）。
4. **探针生成**：statechart 可生成走查路径（哪条转换没被实机走过=取证缺口）——与实机走查取证闭环。

## 3. 新门禁候选：statechart-gate（强制候选第 10 项，带作用域）
- **作用域**：多状态功能面（≥3 状态或含异步流转的功能）——单态小件豁免（豁免梯度）。
- **检查**：①翻译表存在对应 statechart 定义 ②无死端（非终态全有出边）③全可达 ④错误态必须有恢复转换（出路）⑤守卫条件在翻译表有行。
- **分级**：①③④机器可查（exit 1）；②⑤半自动（有定义即过，语义归 critic）。

## 4. 判定表候选（statechart 域）
| # | 触发场景 | 判断 | 行动 | 出处 |
|---|---|---|---|---|
| H1 | 功能面 ≥3 状态 | 无状态机定义=结构层缺失 | 先写 statechart 再写组件 | Harel/XState |
| H2 | 任何非终态 | 无出边=死端 | 补恢复/逃逸转换 | Nielsen #3 |
| H3 | 错误态 | 只有进入没有恢复 | 必须有恢复转换+出路 | Nielsen #9 |
| H4 | 并行子状态 | 扁平枚举组合爆炸 | 层级状态/并行区域建模 | Harel |
| H5 | 转换无守卫说明 | 竞态/重复触发 | 守卫条件写入翻译表 | XState guards |

## 5. 与既有件的关系
六问=状态设计的**问题源**（每问答案落成状态与转换）；六态=**渲染视图**；态+转换矩阵（statechart）=**结构源**（单一权威，表格与走查路径都从它派生）；spec-trace=**实现追溯**；statechart-gate=**结构门禁**。工件链闭环：功能句→翻译表→statechart→矩阵视图→spec-trace→走查→账本。
