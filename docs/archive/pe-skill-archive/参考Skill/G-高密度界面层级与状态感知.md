## 1. 层级系统——高密度不乱的第一原因

1. **z 轴语义（elevation=空间层级）**：Material Design 的海拔系统——页面(0)<卡片(1)<弹出(3)<抽屉/对话框(6-24)；阴影不是装饰是「这层东西在空间上更高」的语义。判定：任何浮层必须携带与层级匹配的 elevation 表达（阴影/遮罩/边框至少其一）。
2. **信息层级三因子**：字号、字重、颜色对比——每维只用 2-3 档（Material type scale：display/headline/title/body/label/caption）。判定：一屏内字号档位 >4 即层级失控；层级靠**组合**（小+中对比+重字重）而非单维堆砌。
3. **格式塔分组**：接近性（相关的靠近，替代画框线）、相似性（同类同样式）、共同命运（一起动的算一组）、图形-背景（弹层+遮罩）。判定：分组优先用间距（接近性），线框是最后手段——高密度界面的乱多源于「框中框」。
4. **留白与墨水比**：Tufte data-ink ratio——删非数据墨水；间距走 4/8pt 网格，间距档位少=节奏感。判定：间距值出现非网格档位=密度失控前兆。

## 2. 密度系统

1. **高密度≠小字**：=去装饰（data-ink）+紧间距+**灰阶分层**（主信息高对比/次信息中对比/元信息低对比）——「灰阶即层级」。
2. **密度可切换**：Ant Design 表格密度、Salesforce Lightning density settings——紧凑/标准由用户按场景选（监控大屏 vs 移动端）。判定：高密度功能面应提供密度切换而非拍死一档。
3. **每行一个主操作**：行内多动作收进溢出菜单（…），悬停/长按显现次级操作——密度与可达性的平衡。

## 3. 状态变化的感知（用户点名「功能处于各状态的变化动感知」）

**认知科学根=变化盲视（change blindness）**：人对无过渡的突变经常失察——状态变化必须携带可感知标记，这是底线级要求不是装饰。

1. **过渡语义**（Material Motion）：container transform（身份连续：卡片→详情页）、shared axis（方向与因果：列表推进）、fade through（层级切换）。判定：态间转换动画必须选对语义，禁止「为了顺滑」乱用（emil 动画四问的补充答案）。
2. **加载态不跳版**：骨架屏保持布局稳定（防 layout shift/CLS）优于居中 spinner——高密度界面的跳动=灾难。
3. **数据更新可感知**：新插入行 flash 高亮渐隐（GitHub/Linear 式）、未读 badge、相对时间戳（"3 分钟前"）、乐观更新（先变再确认，失败回滚+通知）。
4. **不可用与可用态的转换**：按钮 disabled→enabled 必须有可感知变化（颜色+可点性），且 disabled 不能是唯一状态线索（vercel：不单靠颜色）。

**与方向档接口**：六态矩阵定义「有哪些态」，本档补「**态间转换必须可感知**」维度——六态矩阵升级为**「态+转换」矩阵**（每个态间箭头标注：过渡语义/时长/可中断性）。归入双底双顶的「不难用（底线）：变化盲视=无标记的突变是缺陷」与「更好看（上限）：过渡语义正确」两层。
