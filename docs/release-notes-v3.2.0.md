# v3.2.0 发行说明（2026-09-20）

> 本版主题：**外部评审审计 + 条款级落刀**——给治理体系补上「清单外风险」「证据层级」「记忆体积」「评测诚实」「副本一致性」五个缺口。

## 一、这一版解决什么

一份外部评审意见（12 项观察 / 12 项缺陷 / 最严重 5 项）与本仓自证体系对撞后，审计认定「成立 5 项 / 部分成立 6 项 / 误读 1 项」，其中 6 项需要改条款。本版把它们全部落地并逐项验证。

## 二、新增条款（细则 373 条 / 30 类，编号至 `#374`）

| 条目 | 内容 | 为什么 |
| --- | --- | --- |
| `细则 #370` | **L3 清单外高危域执行层枚举**：CI/CD·DNS·IAM·计费·feature flag·webhook·限流·OAuth 回调·生产配置写——命中即至少按 L3 停点问询；**封闭清单语义不变** | 清单的可测试性靠「不扩项」换来，真实危险却按影响面分布 |
| `细则 #371` | **`GATE` 验证层级 `ev=`**（exec / cover / invariant / indep）：L2-F 与高风险任务至少含一项非执行证据；**12 字段定版不变**，`ev` 为可选扩展键 | 执行证据证明「跑过」，同源错误会污染执行证据；非执行证据才触及「跑对」 |
| `细则 #372` | **记忆档双指标上限**（行数 × 体积先到者）+ 机械归档（移动非删除）+ 活头部时间戳校验 | 单一行数阈值可被长行绕过（实测 281 行承载 261.5 KB） |
| `细则 #373` | **机器事实优先于 LLM 判据**；公开数字须有随仓可复算工件；效果类主张在**外部盲评**前不得作为结论 | 判据本身也是被测对象，机器事实引入的被测对象最少 |
| `细则 #374` | **注入副本内容哈希验收**（版本串一致 ≠ 内容一致）；分发形态方向=不可变包 + 薄适配 | 副本链条越长漂移面越大 |

另：`细则 #266` 的「≥2 种负载形状」就地澄清为**下限**（按风险选最富信息量的负载，不是固定数量指标）。

## 七、已知边界（诚实声明）

1. 本版**不宣称效果优势**：现有证据只证明「系统符合作者定义的行为规范」，不证明真实任务正确率提升；盲评实验设计档见 `docs/design-specs/blind-eval-design.md`（未跑批）。
2. `risk_scan.py` 是**关键词召回端口**，非判级权威；召回率/误报率未实测。
3. `ev=` 未对存量高风险场景追溯加严；既有矩阵结论不因本变更失效。
4. GUI 长活会话吃旧注入快照——**升级后须重启应用 + 新开会话**（验收锚：在场提示 · v3.2.0 + 373 条细则 + `zxc663`）。
5. **`ev=` 实弹未稳定（本版最大已知缺口）**：金样本正负对照 23/23 证明判据本身可用，但**实弹 1/3** 说明「条款在场 ≠ 条款被消费」——明示要求写 `ev` 的 prompt 下仍有 2/3 未输出该字段。**不宣称本版已让 `ev=` 行为面落地**；候选改进（重开条件）：① hooks 每轮提醒行补 `ev` ② SKILL §2.5 步 9 出口产物显式要求 `ev` ③ 高风险场景探针矩阵化加严后复采。
