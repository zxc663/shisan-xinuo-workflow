## B 组总蒸馏

**最强 3 机制**：
1. **出口产物门禁链+证据化 GATE**（workflow:113,168-169）：「上一步产物不存在不进下一步」「可重跑工件>自我叙述」「完成=证据+用户验收」+caps/ev 双字段——把假完成变可机检的唯一硬机制。
2. **复用五问与懒人阶梯的同构判定链**（flows:215-223+ponytail:35-43）：两套独立演化的 Skill 给出同一条链，交叉验证=打问题②的成熟形态；配「无归因=违规绕行」。
3. **反借口表+危险词触发+单行判定输出**（workflow:177-188+ponytail-review:13-48）：借口→反驳成对、触发器前置、输出锁死单行+唯一量化指标。

**skill-creator 形态规范要点**：frontmatter pushy description（枚举口语触发词）；三层渐进加载（<500 行）；祈使句+why+例子胜过规则；busywork=过度 prescribing 做减法；2-3 真实提示词验收。

**产品工程 Skill 吸收清单**：
1. 三层结构映射三层加载：SKILL.md=判定表骨架+四问题域路由；references/=注册表+账本+反借口表；scripts/=门禁脚本。
2. 判定表行准入测试：session-knowledge「不能改变下次判断就删」+rule-optimizer「写得出做 X/不做 Y 才算改变行为」；行 schema=`触发场景｜判断｜行动`+代码级正反例（ponytail-review 委婉反例 vs 单行正例对照写法）。
3. 复用链为注册表主索引，未命中自研必须写「闲置归因」；门禁加 caps 检查——该用组件库却自写且无归因=不通过。
4. 交互走查取证：frontend 铁律「以用户在交互点看到什么为准」——门禁强制双视口截图+DOM 证据，不接受口头「体验没问题」。
5. 反借口表独立成节：借口→反驳成对+危险词触发器+输出锁死单行。
6. 质询环节 `disable-model-invocation: true` 手动点火；问题链用 ask-user schema 拼装。
7. 防膨胀三闸：五问准入+账本 3 条上限 5+索引 20 条+引用编号不复制正文（roles 防棘轮）。
8. 触发词覆盖四问题域口语：「丑」「难用」「反直觉」「为什么不用现成的组件」「这功能好像没用」+英文等价——写进 description 且 pushy。
