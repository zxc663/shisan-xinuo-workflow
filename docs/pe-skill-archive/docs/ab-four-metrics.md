## 0 度量总原则

1. **只数实物，不数自述**（N4 教训）：所有指标从工作区工件+可重跑命令提取，禁止采信代理回报。
2. **同任务同条件**：A/B 各自独立工作区+同一份任务书；差异只在「是否加载产品包」。
3. **每组 N≥3**（模型随机性）：单格 N=1 只能说「本实验中」。

## 1 defect_escape（遗漏缺陷率）——核心指标

- **什么算一个「遗漏状态/缺陷」**：交付后被**独立评审员**（未参与实现、拿到任务书+交付物）发现的以下任一项：
  ①任务书明示的功能缺失或行为不符；②用户路径无出路（死端/无提示/不可撤销却承诺可撤销）；③承诺-能力断路（文案/按钮宣称的能力无实现入口）；④态缺失（加载/空/错误/边界任一态无处理）；⑤数据损失路径（刷新/并发/损坏存储下丢数据且无警示）。
- **判定程序**：评审员产出缺陷清单 → 主会话逐条复现（可重跑命令/截图）→ 复现成功计 1。
- **escape 定义**：缺陷在交付物中存在且**实现方未在报告/账本中自报**。自报了的算「发现」，不算 escape。
- **分母**：评审员确认的缺陷总数。

## 2 rework（返工量）

- **口径**：交付 commit 之后（以最终交付 commit 为界）因缺陷产生的修复 commit 数＋其 diff 行数。
- **冷启动实验的等价物**：单轮交付无 R2/R3 时，用「实现过程中 `git log` 里标记为 fix/修复 的 commit」近似，并如实标注口径为近似。

## 3 coverage（验证覆盖）

- **口径（可数清单）**：①门禁运行数/应运行数（statechart+spec-trace+registry+product-object）②evidence 文件数与类型（截图/DOM/可重跑命令）③断言总数中「负路径断言」（非法输入/失败/边界）占比。
- **不算覆盖**：测试文件的存在；只有运行记录（命令原文+退出码）算。

## 4 cost（成本）

- **口径**：token（代理实耗）·工具调用次数·墙钟时间，三者分开报，不合并成单一分数。
- **已知先行数据**：终极命题实验 token 曲线（甲 609→438→269 万递减 vs 乙 264→617→328 万暴涨）；冷启动显式组单样本 ~4.4M/1.7M token（N2/N6c）。

## 5 可证伪判据（承 three-definitions §4.3）

- 理论成立：高风险任务 defect_escape 显著下降，且低风险/小任务 cost 增幅 <20%（档0/档1 豁免梯度应吸收成本）。
- 理论不成立：全部任务 cost +30~50% 而质量只小幅改善——「正确但昂贵」，理论死。
