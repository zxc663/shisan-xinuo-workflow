# 终极命题对照实验协议（2026-09-21 07:00 开跑，09:00 停）

> 命题（direction §四）：同任务双会话对照——用 Product Skill 的一方是否**更少另造、更少偏离、更少维护债、产品状态更易继承**。

## 变量控制
- 同任务文本（下）、同模型、同 yolo 权限、同轮次节奏；唯一变量=是否使用 `shisan-xinuo-product`。
- 甲组（用）：prompt 追加「开工前先加载 shisan-xinuo-product 技能并按其流程执行」。
- 乙组（不用）：prompt 追加「不要加载或使用 shisan-xinuo-product 技能」（其余不限——工作流硬注入两组同在，如实声明此为不可控本底）。
- 工作区（中文，D 盘）：`D:/工具箱对照-甲用Skill/`、`D:/工具箱对照-乙不用/`，各自 git init。

## 任务文本 R1（两组逐字一致）
做一个炫酷的工具箱网站：单页应用，包含至少 6 个实用小工具（如 JSON 格式化、颜色工具、正则测试、时间戳转换、Markdown 预览、密码生成），要求视觉精致、交互流畅、代码结构清晰可持续维护。完成后启动本地服务验证可访问。

## 轮次（每轮 zcode -c 续会话）
- R1 建站（任务文本）。
- R2 「再加 Base64、二维码、Diff 对比三个工具；然后审视现有代码，把不一致、重复或违反你既定结构的地方修正。」
- R3 「以新接手开发者的视角检查全站：有没有点了没反应的按钮、说能做但实现没有的功能、口径不一致的展示？发现即修，修完报告清单。」

## 度量（每轮后跑 scripts/experiment-metrics.py）
①LOC/文件数（git diff）②内联 style=/硬编码 #hex 计数 ③TODO/空 catch/console.log 计数（占位与死代码迹象）④工具数（实际兑现 vs 要求）⑤重复实现迹象（同名/相似组件文件）⑥定性：R2/R3 是否违背或重造前轮结构（继承性）。

## 判读（09:00 收尾）
四维度对照+门禁（statechart/spec-trace 若甲组产出则跑）+结论只答一句：命题成立/不成立/不可判定，证据列出。
