# 怎么验证一条 agent 规则真的有用 · 实证方法论（可移植版）

> 来源：shisan-xinuo-workflow 仓 v1.9→v4.0.0 的验证实践蒸馏（2026-08-26 → 2026-10-10）。目标读者：写 agent 规则 / skill / 系统提示词的人——你们全都有「规则写完没法证明有用」的问题。本文只讲方法、反例与适用边界；证据位全部锚定本仓工件，可逐条复核。
> 诚实前提：本方法论自身的三层完成度=层 1 已证、层 2 部分证、层 3 待证（见 §0）。抄方法可以，别连未证的结论一起抄走。

## §0 问题定义：三层缺口

**规则在场 ≠ 被遵守 ≠ 有用。** 三个层次，三种验证物，缺一层就宣传下一层，是本领域最常见的夸大。

| 层 | 问的是 | 验证物 | 常见冒充 |
| --- | --- | --- | --- |
| 1 在场（delivery） | 规则文本到达模型上下文了吗 | 部署面机检：内容哈希、锚点 grep、请求体解析 | 版本号一致（≠内容一致） |
| 2 遵守（compliance） | 行为符合规则吗 | 行为面证据：探针+判分，只认请求体/rollout 层 | Agent 自报「我遵守了」 |
| 3 有用（efficacy） | 遵守带来更好结果了吗 | outcome 对照：事故/返工率、双臂、第三方复现 | 用层 2 的合规率冒充 |

坑位实录：绝大多数规则工程只做层 1，然后宣传层 3 的收益。本仓自己也在还层 3 的债（事故/未遂账 2026-10-10 起累积，90 天窗）。

## §1 判据版本化（判据即代码）

**规则**：凡「判某行为合规/不合规」的逻辑，必须是代码，且带三件套——①版本号（JUDGE_VERSION）②金样本回归（正例必放行、负对照必拒，改判据必过）③一行变更留痕。

**为什么**：LLM 判据会**滞后**（新合规形态被旧词表误杀=假 FAIL）也会**自满足**（`'effort=' in output` 被 GATE 字段名自身满足=判据空转）——两类事故本仓都实测发生过。

**最小实现**：判分函数+`--judge-selftest`（零 API 成本）+ CHANGELOG 式判据日志。金样本按「运行时真值偏移」构造，真值演进后自测仍成立。

**证据位**：`docs/roadtest-scorecards/JUDGELOG.md`（j1.0→j2.5 变更史，含三次滞后假 FAIL 与两次自满足修复实录）。

## §2 逃逸分析 → 回流闭环（试金石模式）

**流程**：造「现实中等水平」的合成产物（夹具）→ 跑你的门禁 → **逃逸分析**：逐条枚举夹具中真实存在、但门禁没抓到的缺陷 → 三态判定（真缺口 / 半缺口 / 判定域边界外）→ 真缺口**回流成新判据**（带正反自测）→ 复跑必须命中。

**效力证据形态**：带星行「回流前不命中、回流后命中」就是回流效力的直接证据——比任何合规率都硬。

**关键纪律**：不是所有漏抓都是缺口。逐条做**判定域裁决**（人工域？粒度取舍？声明边界？），防把「设计如此」当「坏了」修。

**证据位**：`docs/field-trials/jz-01…07/SCORECARD.md`（7 张合成卡、13 个 checker 缺口回流；jz-02 卡含回流施工时自抓 bug 的实录）。

## §3 反向变异自测（自测只盖正向）

`--selftest` 全 PASS 只证明**正向样例判得对**，不证明**坏形态拦得住**。两者并存是实测事实，不是理论风险。

**修法**：每条判据配反向变异样例——把你想拦的坏形态显式构造出来，断言它被拦。类型穿透、变体绕过、枚举死代码、空值吞检是最常见的四类漏报面。

**证据位**：`docs/reverse-injection-gates-20260929/REPORT.md`——27 例变异：selftest 全 PASS 与**漏报 15** 并存，每例附根因与修法。

## §4 双臂对照与作者污染

**问题**：判分器、夹具、被测物同一作者=自证结构。缓解按成本升序：

1. **预注册**（近零成本）：判据、口径、中止条件**先写死再跑**，防事后挑口径——本仓计划书/判读口径 5 条即此。
2. **双臂对照**（低成本）：同任务 with/without 各跑一遍（treatment/stock 形态，superpowers-evals 的产品化先例）；n 小仍可看方向。
3. **独立判分**（中成本）：判据不进被测上下文+独立 assessor 事后判分。
4. **第三方复现**（最硬）：别人 clone 你的仓库跑一遍。

**本仓诚实现状**：①已做；②部分（工具箱双仓 n=1）；③④未发生——「第三方」至今 0 次。抄走 ①②就能超过大多数同行，③④留到你真要对外主张效力时。

**证据位**：`docs/comparison-v290-analysis-20260916.md` 附录（superpowers-evals 真身三形态分析）。

## §5 环境失败与无效样本纪律

探针会死于环境（配额/网络/平台限制）≠ 行为失败。**环境死亡行必须带证据签名**（provider 报错栈原文），且**不进分子分母**。

两条对称的坑：把环境死算成行为退化（假 FAIL）；把真退化藏进环境死（假绿）。签名+单列是唯一解。本仓实测：1047 探针行中 717 行作废（68%，provider 欠费窗沉积）——不剔会得出错误的行为结论，剔完剩余样本量才诚实。

**证据位**：`docs/roadtest-scorecards/README.md` 判读口径 5 条+作废签名机制。

## §6 负面结论更严

判「不复现 / 不存在 / 没推上去 / 没生效」的举证责任**高于**正面结论：判据逐字对齐+真实调用链（禁自造模拟）+对照组；不满足就降格「未定论」。

实录（自罚公开）：本仓曾把「核验连接超时」误读为「推送失败」并写进断言——实际远端早已成功，靠 API 读回复核才归位。负向结论必须过**通道复核实证**再下笔。

## §7 适用条件与过重判定（何时别用）

**值得上这套**：规则被高频复用 / 高危域（密钥、删除、发布）/ 多平台分发 / 需要对外证明效力的公开主张。

**过重**：n=1 一次性场景、无基线可比、单人一次性脚本、纯文档变更——直接人工复核更便宜。验证体系自身的 token 与维护成本是真实的，别为了仪式感燃烧。

**最小可用子集**（按 ROI 排序，抄这四件就能起步）：
1. 判据即代码+金样本回归（§1）；
2. 反向变异样例（§3）；
3. 逃逸分析→回流（§2，需要能造夹具）；
4. 环境死亡签名（§5，一旦你跑批量探针）。

双臂对照与第三方复现只在你要**对外主张效力**时才需要。

**元提醒**：验证体系自身也会熵增（判据越来越多、口径越来越深）。给它设**冻结点**（本仓判据 j2.5 / 聚合器 a1.1 冻结=2026-10-10 起）和**退役机制**（零命中≠无用，但「只进不出」的规则库注定失控）。
