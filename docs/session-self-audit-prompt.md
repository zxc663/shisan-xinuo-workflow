# 会话自查导出提示词（供复制到任意目标会话使用）

> 用法：把下方分割线内的全文粘贴到你想审计的会话（ZCode / WorkBuddy / 其他平台均可），该会话的回复即为「Skill 在该会话中的应用情况自报」；将回复带回本仓与机器侧 scorecard 对照（平台审计计划 §4）。可逐会话重复使用。

---

【会话工作流自查导出】请对你当前会话做一次诚实自查，逐项回答。核心纪律：**任何一项如果没发生过、没见到、不确定，直接写「未发生/未见到」——禁止推测、禁止把「应该发生过」写成「发生了」；所有断言优先给原文摘录而非概括。**

**1. 注入面**：你的上下文（系统提示 / 规则文件 / 项目说明）里是否出现过「十三希诺工作流」或 shisan-xinuo-workflow 相关内容？
- 若有：①摘录你实际看到的关键指令原文（3-5 条，逐字）②它们出现的位置（系统提示开头 / 中部 / 规则文件 / 其他）③你判断它们是每会话固定注入、还是按需加载的依据
- 若没有：明确写「本会话未见任何相关注入」，并简述你实际收到的系统指令是什么形态

**2. 加载面**：本会话你实际 Read / 打开过哪些与该工作流相关的文件（SKILL.md / references/ 下任何文件 / 模板 / detail_lookup 脚本）？各在什么时机、出于什么原因？如果一次都没读过，直接说明「文件级加载 0 次」。

**3. 行为面**：对照下列纪律动作逐条回答「发生了 / 没发生」，发生了的给出本会话具体实例：
① 开工复述（动手前把任务目标先复述一遍）
② 判级（L1 / L2-S / L2-F，或说明你没用过这个分级）
③ 承载检查（读取或创建 memory/agent-log.md）
④ 必问确认（在动手前向用户提澄清问题；若提了但没得到回答，说明你之后怎么处理的）
⑤ GATE 验证块（任务收尾的可复跑验证声明）
⑥ 细则引用（`details #NNN` 或 `细则 #NNN` 形态的引用）
⑦ 错误时检索端口（detail_lookup.py 的真实执行）

**4. 解读面**：你对这套指令的整体理解——它要求你做什么？哪些你觉得合理、哪些觉得多余或矛盾？有没有哪条你**理解了但没执行**？为什么（上下文太长 / 与任务无关 / 与其他指令冲突 / 成本考虑 / 其他）？

**5. 元问题**：如果让你改进这套指令的触达方式（让它在像本会话这样的真实任务里更可能被真正执行），你会改什么？

输出为结构化 markdown，按 1-5 编号；长度不限，但每条结论必须有证据（原文摘录或具体实例）支撑。
